# Девять тестов из «новые_тесты_ТЗ_готово.xlsx»

Реализация: `src/lib/exercises/protocol`. Все девять тестов доступны в каталоге
упражнений; URL используют точные `test_type` из Excel, например
`/exercises/memory_matrix/about`. Существующие тесты и последовательность ГТО
не заменяются. Новые тесты не добавляют медалей и нормативных баллов в профиль;
для этого нужны результаты пилота. Связи с навыками указаны в `config.ts`.

## Временный лексикон

По согласованию с пользователем «Лексическое решение» использует 40 настоящих
слов из Excel и случайные произносимые псевдослова. Проверка по полному словарю
русских словоформ и ручное утверждение **ещё не выполнены**: случайный кандидат
может оказаться редким настоящим словом. Оговорка видна перед тестом и в результатах.
В истории сохраняются `dictionary_provisional=true` и версия
`temporary-unverified-1`; такие сессии не допускаются в профиль.

`lexicalPlan()` принимает записи с `review_status`, версией морфологического
лексикона и шаблоном генерации. Для замены временного генератора необходимо
подготовить утверждённые записи обоих классов/уровней, проверить псевдокандидатов
по полному словарю лемм/словоформ и исключениям и заменить `draftLexicalPlan()`.
Старые предъявленные строки сохраняются и не переоцениваются как новый лексикон.

## История и схема

Используются существующая `session` и новая `protocol_trial`: одна строка на
реально предъявленную пробу/матрицу, уникальность `(session_id, trial_index)`.
Все специфичные поля из листов «БД попытки» и «БД стимулы» хранятся в проверяемом
JSON `data`: стимул, ответ, времена, последовательности выделений, вложенные раунды
и события суммы. Это сохраняет связи board→round→event без отдельных таблиц
на каждый вид события. Справочник признаков и исходных настоящих слов импортирован
из Excel в версионированный `dictionary.json`.

Сервер пересчитывает корректность, пути слов, заблокированные клетки и summary
по истории; отклоняет несовпадение. Сохранение сессии и проб — транзакционное,
повтор с тем же sessionId идемпотентен. Низкая точность не означает техническую
невалидность; таймауты фиксированных вопросов не допускаются в профиль.
Фальстарт тоже не является зачётной реакцией. Минутный лимит поиска/сумм — штатный.

При выходе сохраняется неполная история, без фиктивных проб. Закрытие страницы
поддерживается синхронным локальным черновиком и восстановлением в существующую
очередь при следующем открытии теста. Монотонные браузерные времена не вычитаются
из UTC-дат. RT цвета и моторной реакции привязан к requestAnimationFrame.

В репозитории `drizzle/` исключён из git; как и для существующих таблиц,
миграции генерируются из схемы (`npm run db:generate`, в Docker автоматически).
Для существующей локальной БД применить схему: `npm run db:push` с нужным
`DATABASE_URL`. Перед изменением реальной БД рекомендуется штатная резервная копия.

## Проверка

- `DATABASE_URL=:memory: npx vitest run --project server`
- `npx vitest run --project client src/lib/exercises/protocol/Playground.svelte.test.ts`
- `DATABASE_URL=:memory: npm run build`

Основные сценарии: ровно десять проб памяти; ошибки и таймауты не уменьшают уровень;
палиндром и повтор пути не удваивают очки; сумма принимает альтернативное решение
и непустой нулевой набор; дедлайн общий; фальстарт до фактического зелёного кадра;
положительный RT меньше 300 мс допустим; подмена summary/клеток отклоняется сервером.
